iDezign Toolkit - Changelog
===========================
Versioning: minor bump (x.Y) for tweaks & fixes, major bump (X.0) for big changes.
The version shown in the launcher's title bar comes from "toolkitVersion" in
iDezign_Versions.json - bump it there with every change.

v3.4.3 - 2026-07-03 - Launcher: suppress the PowerShell console windows (GUI-only experience)
  * Double-clicking the .exe used to pop a chain of console windows (cmd
    from the .bat, PowerShell, elevated PowerShell) and the last console
    stayed open BEHIND the GUI for the whole session. Two changes:
  * GUI (v2.9.3-hide-console): hides its own console via ShowWindow(
    GetConsoleWindow(), SW_HIDE) right after startup. Deliberately NOT
    '-WindowStyle Hidden' at launch - AppLocker/Smart App Control kill
    elevated PowerShell that starts pre-hidden (malware-loader pattern,
    see v2.9.1 notes). Visible launch + immediate self-hide passes those
    policies; the console is a sub-second flash instead of a permanent
    background window.
  * iDezign TOOLKIT.bat (v2.9.2-bat): self-minimizes on first launch
    (relaunches itself with start /min, so the console is a taskbar blip)
    and the elevated PowerShell spawns with -WindowStyle Minimized
    (minimized is a normal visible launch, unlike hidden). Net result:
    double-click .exe -> UAC prompt -> GUI. No console popups on screen.
  * Tools launched FROM the menu (Cleanup, Diagnostics, etc.) still open
    their own PowerShell windows - those are interactive consoles by
    design.

v3.4.2 - 2026-07-03 - Cleanup: WU scan recovery + shadow deletion via WMI (both from live field run)
  * Cleanup Phase 0: Get-WindowsUpdate "Value does not fall within the
    expected range" (known PSWindowsUpdate first-run WU-agent issue,
    GitHub #14) was being swallowed - the catch set $updates=@() and the
    script printed a green "Update phase complete" WITHOUT having scanned.
    False success: machine left unpatched, tech none the wiser. Now:
    register the Microsoft Update service (7971f918... - required for
    -MicrosoftUpdate), restart wuauserv+bits, retry with -MicrosoftUpdate,
    then retry as plain WU. Only if all three fail does the phase end,
    and it ends with a YELLOW "updates were NOT checked, run manually"
    warning instead of a green all-clear.
  * Cleanup Phase 2-7/8: "ERROR running vssadmin delete shadows: The
    system cannot find the file specified" persisted even after the
    v3.2.1 full-path-resolution fix - and DISM launches fine through the
    same helper on the same machine, so vssadmin.exe itself is missing/
    unreachable (newer Win 11 builds strip legacy VSS tooling; AV also
    targets this exact command). Shadow deletion now uses the
    Win32_ShadowCopy WMI class first (the API vssadmin wraps, no
    external exe needed, reports the count deleted), with vssadmin kept
    only as fallback if WMI errors.

v3.4.1 - 2026-07-03 - Migrate: fix exit-16 robocopy failures with paths containing spaces
  * iDezign_Migration_Utility.ps1 - Invoke-Robocopy was failing with
    "exit 16" in ~2 seconds on every folder when the destination path
    contained spaces (e.g. "D:\Paul A BU\Backup_..."). Not a single
    file was copied - directory was created, but robocopy exited before
    reading a byte. Root cause: the helper used Start-Job with
    param($args) inside the ScriptBlock, which shadowed PowerShell's
    automatic $args variable, and passing the arg array through Start
    -Job's IPC boundary mangled paths with spaces (robocopy saw
    "D:\Paul", "A", "BU\..." as three separate args). Fix: rewrote to
    pass Source/Dest/ExtraArgs as NAMED parameters and construct the
    robocopy arg array INSIDE the job. Uses & robocopy.exe explicit
    invocation (not bare robocopy). No more space-related failures.

v3.4 - 2026-07-03 - GUI fallback menu synced to manifest (Duplicate/SyncDrives/DISM)
  * GUI (v2.9.2-fallback-sync): the built-in fallback tool list
    ($DefaultToolDefs) - used only when iDezign_Versions.json is missing
    or unparseable - was still the old 6-tool lineup (no DISM, no Sync
    Drives, no Duplicate, and still offered the retired SavePDF row).
    Synced it 1:1 with the v3.3 manifest: 8 tools, same order, same

    present - no behavior change on a healthy install.

v3.3 - 2026-07-01 - New Duplicate tool + Cleanup Preflight moves Chrome/MWB early
  * NEW tool: iDezign_Duplicate.ps1 - one-way copy between any two
    locations. Handles folder<->folder, drive<->drive, USB, CD/DVD,
    network shares uniformly (all just paths under the hood). Robocopy-
    based with three modes:
      M - Mirror   : dest becomes exact copy of source (deletes extras)
      A - Additive : copy source -> dest, no deletions on dest
      D - Dry-run  : preview without touching files
    Retry-limited (R:1 W:1) to avoid the default robocopy 30-minute
    per-file hang on locked files. Multithreaded (/MT:16), exclude
    junctions (/XJ) to prevent infinite loops on system drives.
    Interactive prompts for source, destination, mode - drag-drop from
    Explorer into the console auto-fills paths. Log file written next
    to destination for audit. Registered in the manifest as tool #7
    (icon 📋), reordering Reset-to-OOBE to slot 8.
  * Cleanup: Preflight quick-installs before the WU loop. Chrome install,
    Chrome default browser, and Malwarebytes download all moved to a new
    [Preflight] region that runs AFTER prompts but BEFORE the multi-hour
    Windows Update loop. Fail-fast: if a download URL is broken you know
    in 60 seconds instead of 3 hours in. Chrome default is set early so
    browsing during the update loop uses Chrome. State-gated (Preflight
    Done flag) so Phase 1a/1b/1d skip on resume after WU reboot.

v3.2.2 - 2026-07-01 - Three Cleanup fixes from live field run (rename, resume, WU loop)
  * Phase 4 rename: 'Rename-LocalUser' fails on Win 11 25H2 same way
    Get-LocalUser did for REPAIR. Added ADSI (WinNT provider) fallback -
    (`[ADSI]"WinNT://.../CurrentUser,user"`.psbase.Rename()). ADSI works on
    every Windows version regardless of LocalAccounts module state.
  * Resume-after-Windows-Update-reboot: switched from HKLM RunOnce (fires
    in user's context, needs UAC, dies when user has a login password) to
    a ScheduledTask with AtLogOn trigger running as SYSTEM elevated with
    highest privileges. RunOnce is kept as belt-and-suspenders fallback in
    case the task subsystem is corrupted or GPO-blocked. Fixes "if there
    is a password for the user to put in I have to start the entire
    Cleanup script over" reported from live field run.
  * Phase 0 WU loop: after a successful install pass with no reboot
    required, force a fresh UsoClient StartScan + 20s wait before the
    next Get-WindowsUpdate call. Without this, PSWindowsUpdate's cached
    scan state makes the next pass return empty even when Defender/driver/
    prereq-gated updates are pending, causing the loop to declare "done"
    prematurely. Fixes "Windows update doesn't loop anymore" reported
    from live field run.

v3.2.1 - 2026-07-01 - Fix "system cannot find the file specified" for vssadmin/dism/msiexec
  * iDezign_Common.psm1 - Start-ProcessWithTimeout now resolves bare
    executable names via Get-Command -CommandType Application before
    invoking, with a SystemRoot\System32 fallback. Root cause: Process.
    Start(psi) with UseShellExecute=$false calls CreateProcess, whose
    PATH-search semantics are unreliable across process bitness / current
    -directory context. Symptom: Cleanup Phase 2 step 7/8 (vssadmin delete
    shadows) threw "Exception calling 'Start' with '1' argument(s): The
    system cannot find the file specified" on Eric's live run. Same latent
    bug affected msiexec (Phase 1d Malwarebytes install) and three dism
    calls (Phase 2 step 8/8 component cleanup + resetbase). All fixed via
    the central helper - no changes needed at the call sites.

v3.2 - 2026-07-01 - Cleanup: hardware-aware vendor driver tools install (Phase 1l)
  * NEW Cleanup Phase 1l - Install vendor driver management tools.
    Detects hardware at run time via CIM and installs the matching vendor
    driver management app so the customer has one-click driver/firmware
    updates after we leave. Detection matrix:
      Dell mfr           -> Dell Command | Update            (winget)
      HP / Hewlett mfr   -> HP Support Assistant             (winget)
      Lenovo mfr         -> Lenovo Vantage                   (msstore)
      Intel CPU / silicon-> Intel Driver & Support Assistant (winget)
    (Realtek Audio Console was planned but dropped: the standalone
    Microsoft Store listing 9P71VC01SBTL was pulled in 2026 - the URL
    now returns ProductNotFound. The console still ships bundled with
    OEM driver packages, which Dell CU / HP SA / Lenovo Vantage already
    apply as part of their own driver-update flow. So it's covered.)
    Skipped entirely on Windows Server - server SKUs use SCCM/Intune/vendor
    server tooling (Intel DCM, HP Smart Update Manager, etc.), not the
    consumer tools shipped here.
  * NEW helpers - Ensure-Winget (bootstrap App Installer if missing;
    downloads the .msixbundle from aka.ms/getwinget and installs via
    Add-AppxPackage) + Install-OrUpgrade-Winget (idempotent installer that
    runs 'winget install' if missing OR 'winget upgrade' if already
    installed, always logs the outcome, and silently opens the vendor
    download page in the browser if winget is genuinely unavailable - no
    Y/N prompt mid-run).
  * SITE: /toolkit/ page - split the "Also worth installing" grid into a
    manifest file (scripts/iDezign_SiteContent.json). The JS renderer in
    toolkit/index.html fetches that JSON from jsDelivr and re-populates
    the grid at page load. Adding a new tile is now a JSON edit, not an
    HTML edit. Backfilled 5 new tiles: Windows Update (ms-settings:
    windowsupdate - opens Settings > Windows Update directly on the
    user's PC), Dell CU, Intel DSA, HP Support Assistant, Lenovo Vantage,
    Realtek Audio Console. 12 tiles total (4 rows x 3 columns).
  * CI: new weekly workflow .github/workflows/check-external-urls.yml
    that scans scripts/, toolkit/, help/ for http(s) URLs and HEADs each
    one. On failure, opens a dedup'ed GitHub Issue tagged 'url-rot' with
    a table of dead URLs + which files reference them. Runs Mondays at
    12:00 UTC + on any push to script/site content + manual dispatch.
    Notification path: GitHub emails on the new issue. First real run
    caught 3 issues immediately: (1) fonts.googleapis.com + fonts.
    gstatic.com were false-positives (preconnect hints, don't serve a
    landing page) - added to the skip list, (2) the Realtek Store URL
    was dead (see above), (3) /releases/latest/download/iDezign-Toolkit.exe
    returned 404 because assets were never attached to releases (see
    build workflow fix below).
  * BUILD: .github/workflows/build-toolkit-zip.yml now attaches the
    dist/.zip and dist/.exe to the matching GitHub Release via
    'gh release upload --clobber' after building. Also triggers on
    'release: published' so cutting a new release auto-attaches. This
    keeps the SmartScreen-bypass fallback link on idezign.ai/toolkit
    (Get from GitHub Releases) alive - previously it 404'd since v2.9.1
    because releases were cut but assets were never uploaded.

v3.1 - 2026-06-30 - Server-safe cleanup + REPAIR account fallback + real time drift check
  * Cleanup: on SERVERS the network-adapter DHCP conversion is now SKIPPED.
    Static IP is preserved as-is; the config is still reported for the record.
    Servers need static IPs for domain-controller / file-server / print-server
    workloads - yanking them to DHCP was breaking those setups.
  * Cleanup: computer-rename prompt now shows current computer name before
    asking. User-rename prompt already showed current user; both are now
    consistent. Less risk of accidentally renaming the wrong machine.
  * Cleanup + Diagnostics: the LocalAccounts PowerShell cmdlets (Get-LocalUser,
    New-LocalUser, Get-LocalGroupMember, Add-LocalGroupMember) sometimes fail
    to auto-load on Windows 11 25H2 with a "not recognized as a cmdlet" error
    even though the account subsystem is present. This produced two visible
    bugs: (1) Cleanup could not create/manage the REPAIR account at all, and
    (2) Diagnostics falsely reported "REPAIR MISSING" on machines that had a
    REPAIR account. Fix: try to force-load Microsoft.PowerShell.LocalAccounts
    at the top of the section, then fall back to `net user` / `net localgroup`
    everywhere the cmdlets would otherwise be used. Both scripts now work
    identically on 25H2 machines with or without the cmdlets available.
  * iDezign_Common.psm1 (Sync-SystemTime): the old check only compared local
    time before-vs-after the w32tm resync and said "clock is accurate" if the
    delta was small - which is wrong. w32tm can silently fail (no NTP peer
    reachable, service wedged, proxy stripping traffic) and leave the clock
    drifted while reporting success. New check: after the resync, compare
    local time to an authoritative HTTP Date header (Google, Microsoft, or
    Cloudflare) and warn loudly if drift > 60s. Returns false in that case
    so callers can abort. If HTTP probes all fail too, we say "unverified"
    honestly instead of falsely claiming accuracy.
  * All three scripts have their $ScriptVersion bumped to the new v3.1
    strings so the version-consistency check in CI catches any drift.

v3.0 - 2026-06-30 - Major: Remediation + Save PDF consolidated, Migration goose
  * MENU CONSOLIDATION (the "major" in this major bump): "Save PDF to
    Desktop" is no longer a standalone menu item. Its functionality is now

    iDezign_ServiceReport_<computer>_<timestamp>.pdf, saved to the Desktop.
    The temp source HTML is left in %TEMP% as a manual-fallback option if
    Edge fails for any reason (open in any browser, Print -> Save as PDF).
  * iDezign_Remediation.ps1: behavior when no Diagnostics report is present
    - the PDF still produces, containing just the Remediation summary +
    actions log. Useful when Remediation was run without Diagnostics first.
  * iDezign_SavePDF.ps1: DELETED. Its logic now lives inside Remediation.
    Tech debt going down, not up.
  * Migration icon: 📦 (package) -> 🪿 (goose). On-theme: migrating geese

    (Windows 11 ships these; older Windows 10 builds may show a fallback).
  * Menu after v3.0 (7 tools, OOBE remains at the bottom):
      1. 🔍 Diagnostics
      2. 🧹 Cleanup
      3. 🔧 Remediation        (now produces optional combined PDF)
      4. 🪿 Migrate              (was 📦)
      5. 🩺 DISM
      6. 🔄 Sync Drives
      7. ⚠ Reset to OOBE       [DESTRUCTIVE]
  * Version-bump rationale: per the convention at the top of this file,
    x.0 is a major bump for big changes. Removing a menu item and merging
    its behavior into another is a structural change to the toolkit's
    surface area, so a major bump fits.

v2.9.2 - 2026-06-30 - One-click .exe download (NSIS-based)
  * Toolkit now ships as both a portable .exe AND the existing .zip.
    Double-click the .exe and it silently extracts to %LOCALAPPDATA%\
    iDezign-Toolkit and auto-runs the launcher. No prior installation,
    no admin needed for the extract step itself, fully portable.
  * Behind the scenes: the .exe is built by NSIS (Nullsoft Scriptable
    Install System), the actively-maintained Windows installer maker
    used by Steam, OBS, Filezilla, and thousands of other Windows apps
    since 1995. Initial attempts used chrislake/7zsfxmm (a 2017 SFX
    module) which silently failed to extract on Windows 11 25H2 due
    to Smart App Control + tighter unsigned-EXE rules introduced in
    that build.
  * Both downloads now visible on idezign.ai/toolkit/: .exe is the
    primary one-click option; .zip remains the fallback for AppLocker-
    restricted environments where unsigned .exe extraction is blocked.
  * CI pipeline now builds and commits BOTH dist/iDezign-Toolkit.zip
    and dist/iDezign-Toolkit.exe on every release. Zero manual steps.

v2.9.1 - 2026-06-29 - Launcher .bat + Sync Drives parse fix; bigger GUI window
  * iDezign_SyncDrives.ps1: fixed a parse error introduced in v2.9. The
    $ScriptVersion assignment was placed BEFORE the param() block, which
    makes PowerShell reject [CmdletBinding()] and refuse to load the
    script. The Sync Drives menu item appeared to "do nothing" - the
    elevated PS window opened, hit the parse error, and exited before
    the user could read the message. Moved $ScriptVersion AFTER param()
    (the only valid placement when a script takes parameters) and added
    a comment so the next person doesn't repeat the mistake.
  * iDezign_SyncDrives.ps1: added a "Press Enter to close" pause at the
    end so success summaries and errors stay visible when the script is
    launched from the GUI (which doesn't pass -NoExit).
  * iDezign TOOLKIT.bat: rewrote control flow to use goto labels
    instead of "if (...) else (...)" blocks. CMD's IF/ELSE block parser
    misreads parentheses inside a quoted path - so when the script
    lived in a folder named, say, "iDezign-Toolkit (7)" (the default
    name after a second GitHub-zip extract), the old version silently
    failed. goto-based control flow is immune to that.
  * iDezign TOOLKIT.bat: dropped -WindowStyle Hidden from the elevated
    relaunch. Some AppLocker default rule sets and Smart App Control
    silently kill elevated PowerShell launched with -WindowStyle Hidden
    (it's a known malware-loader pattern). A visible console window
    adds a half-second flash but launches cleanly under those policies.
  * iDezign_Toolkit_GUI.ps1: window Height bumped 480 -> 700 so all 8
    tools display without scrolling.
  * Menu reorder: Reset-to-OOBE moved from slot 5 to slot 8 (bottom).
    Most-destructive-on-the-bottom is a deliberate friction pattern -
    same reason "Delete account" lives at the bottom of every settings
    page on every major web app.
  * Real-world impact: launcher now works cleanly on machines with
    AppLocker enabled, in folders with parens in the path, and the
    menu layout puts dangerous operations behind a deliberate scan.

v2.9  - 2026-06-24  - Sync Drives tool + menu reorder
  * New menu item "Sync Drives": two-way folder/drive synchronizer with
    trash-safety - nothing hard-deleted, replaced/removed files go to a
    dated _SyncTrash folder per drive. State tracking on two-way runs
    correctly distinguishes "added here" from "deleted there" between
    runs. Three modes:
      - Two-way (default): both drives kept in sync, newer file wins
      - One-way mirror: source authoritative, destination becomes a copy
      - Additive: copy new/updated only, never delete on destination
  * Sync Drives includes an interactive drive picker (lists connected
    drives with size + free space + label; accepts a letter or pasted
    folder path), a dry-run mode that previews then offers to re-run for
    real, and per-run log + state file on Drive A.
  * Menu reorder: Save PDF to Desktop promoted to slot 2 under
    Diagnostics (workflow: run diagnostics, then convert the HTML report
    to PDF). Everything else slides down one, Sync Drives lands at 8.

  * GUI: every row now renders the emoji icon from the manifest "icon" field

v2.7  - 2026-06-23  - DISM standalone tool

    CheckHealth (baseline) -> ScanHealth (deep scan) -> RestoreHealth (only

v2.6  - 2026-06-02  - All-profiles cleanup
  * Cleanup script Phase 2 now iterates Win32_UserProfile and cleans Temp,
    Edge & Chrome caches, Recent items, thumbnail/icon caches and INetCache
    for EVERY real user profile on the machine - not just the current admin.
  * Profiles whose user is currently logged in are skipped automatically
    (active processes hold cache files open, so cleaning would error out).
